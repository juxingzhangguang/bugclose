# BugClose 接口测试 — 缺陷与风险清单

本清单由接口自动化套件实测得出，所有条目均可通过对应用例编号复现。

- 被测版本：本地 `local` profile，服务地址 `http://localhost:8080`
- 执行快照：**573 passed / 11 xfailed / 0 failed**，通过率 100.0%，耗时 39.52s
- 用例总数：**440**（自动化 435 + 手工 5），覆盖 12 个模块
- 复现方式：`python -m pytest -m "" -q`，或按编号定位 `python -m pytest -q -k <函数名>`

## 一、判定口径

| 类别 | 含义 | 脚本处理 |
| --- | --- | --- |
| 后端缺陷 | 实际行为明确违背接口语义（应为 4xx 却 5xx、数据不一致） | `xfail(strict=True)`，修复后自动转 XPASS 报警 |
| 安全隐患 | 可被利用绕过防护，但当前实现「按设计如此」 | 断言真实现状 + 备注风险，**不** xfail |
| 现状确认 | 语义/一致性风险，需产品或前端配合决策 | 断言真实现状 + 备注风险，**不** xfail |

> `xfail(strict=True)` 的意义：缺陷未修时套件保持绿色，一旦后端修好，用例会变成 **XPASS 失败**，强制提醒把断言改回正向，避免「缺陷标记」长期沉淀成僵尸。

## 二、后端缺陷（D-01 ~ D-05）

### D-01 字段超长未校验，落库触发完整性异常返回 500

- **等级**：中（可用性 + 错误语义）
- **影响接口**：`POST/PUT /api/projects`、`/api/bugs`、`/api/requirements`、`/api/testcases`、`/api/users`、`/api/roles`
- **现象**：请求体字段长度超过 JPA `@Column(length=...)` 上限时，服务层不做长度校验，直接落库触发 `DataIntegrityViolationException`，全局异常处理器未覆盖，返回 **500** 且携带框架默认错误体。
- **期望**：入参校验阶段返回 **400** `{"error":"名称长度不能超过 100"}` 之类的业务文案。
- **实测边界**：

  | 字段 | 上限 | 触发值 | 对应用例 |
  | --- | --- | --- | --- |
  | 项目 name | 100 | 101 字符 | PROJ-028 |
  | 缺陷 title | 200 | 201 字符 | BUG-010 |
  | 需求 title | 200 | 201 字符 | REQ-011 |
  | 用例 title | 200 | 201 字符 | TC-011 |
  | 用户 username | 50 | 51 字符 | USER-016 |
  | 角色 name | 50 | 51 字符 | ROLE-031 |

- **建议修复**：在各 `validateRequired` 中统一补长度校验（可抽公共 `LengthValidator`，直接读实体注解上限），或引入 `jakarta.validation` + `@Size` 并在 `GlobalExceptionHandler` 中处理 `MethodArgumentNotValidException`。

### D-02 非空枚举字段显式传 null 返回 500

- **等级**：中
- **影响接口**：`POST /api/bugs`（`severity`）、`PUT /api/bugs/{id}`
- **现象**：`severity` 在实体上非空，请求体显式传 `"severity": null` 时校验只判「缺省」不判「显式 null」，落库触发完整性异常 → **500**。
- **期望**：**400** `{"error":"严重程度不能为空"}`。
- **对应用例**：BUG-011
- **建议修复**：必填校验统一用 `== null` 判定而非 `containsKey`；枚举反序列化失败（非法字符串）已由 `IllegalArgumentException` 分支正确返回 400，无需改动。

### D-03 multipart 缺少 file 分片返回 500

- **等级**：中
- **影响接口**：`POST /api/docs`、`POST /api/uploads`
- **现象**：不带 `file` 部分（或 part 名写错）时，Spring 抛 `MissingServletRequestPartException`，`GlobalExceptionHandler` 未覆盖 → **500** 框架默认错误体。
- **期望**：**400** `{"error":"请上传文件"}`。
- **对应用例**：DOC-014、UP-010
- **建议修复**：`@RequestParam(value="file", required=false) MultipartFile file` + 手动判空，或在 `GlobalExceptionHandler` 增加 `MissingServletRequestPartException` / `MultipartException` 处理分支。

### D-04 缺陷序号并发分配重试上限过低

- **等级**：高（数据写入失败）
- **影响接口**：`POST /api/bugs`
- **现象**：`BugService.create` 用 `PROPAGATION_REQUIRES_NEW` 独立事务取 `max(seq)+1`，靠唯一约束 `(project_id, seq)` 兜底，冲突重试上限 **3 次**。6 路并发创建时重试耗尽，抛 `DataIntegrityViolationException` → **500**，部分请求写入失败。
- **期望**：并发创建全部成功，序号在项目内不重不漏。
- **对应用例**：BUG-051（标记 `slow`）
- **建议修复**：三选一 —— ① 改用数据库自增序列表 / `SELECT ... FOR UPDATE` 悲观锁；② 提高重试上限并加随机退避；③ 序号改为「项目内计数 + 唯一约束 + 无限重试直到成功」。需求/用例模块若沿用同一套 seq 分配逻辑，需一并修复。

### D-05 需求所属期创建不 trim，查询却 trim，导致筛选漏匹配

- **等级**：中（数据一致性）
- **影响接口**：`POST /api/requirements`、`GET /api/requirements?period=...`
- **现象**：`RequirementService.validateRequired` 只对 `title` 做 trim，`period` 原样落库；查询侧对 `period` 参数做了 trim。创建时传 `" 2026Q1 "`，之后按 `2026Q1` 筛选查不到该需求。
- **期望**：写入与查询两侧 trim 策略一致。
- **对应用例**：REQ-044
- **建议修复**：`validateRequired` 中对 `period`、`module` 等所有字符串字段统一 trim（与 title 一致）。

## 三、安全隐患（现状确认，建议排期修复）

### S-01 X-Forwarded-For 无条件信任 → 登录限流可绕过

- **等级**：高
- **位置**：`AuthController.clientIp()`
- **现象**：限流键为 `用户名 + IP`，IP 取 `X-Forwarded-For` 第一个值且不做可信代理校验。攻击者每次请求换一个伪造 XFF，即可让失败计数永远落在新桶里，**连续 10 次错误口令全部返回 400，从不触发 429**，限流形同虚设，可离线爆破口令。
- **对应用例**：SEC-006
- **建议修复**：仅在部署于可信反向代理之后时解析 XFF（配置可信代理网段），否则一律用 `request.getRemoteAddr()`；或改由代理层透传真实 IP 到专用头。

### S-02 强制改密标记无服务端拦截

- **等级**：高
- **位置**：`AuthFilter` / `AuthService`
- **现象**：`mustChangePassword` 只作为登录响应字段返回给前端，服务端不做任何拦截。用默认口令 `admin123` 登录后绕过前端直接调业务接口，可长期正常读写数据。
- **对应用例**：SEC-020
- **建议修复**：`AuthFilter` 解析出用户后，若 `mustChangePassword=true`，只放行 `/api/auth/me`、`/api/auth/change-password`、`/api/auth/logout`，其余返回 **403** `{"error":"请先修改初始密码"}`。

### S-03 /uploads/** 无项目级鉴权

- **等级**：中
- **位置**：`AuthFilter` + `UploadResourceConfig`
- **现象**：静态图片只校验登录态，不校验归属项目。任意登录用户拿到 URL 即可读取其他项目的缺陷截图，与业务接口的数据隔离策略不一致。
- **对应用例**：UP-028
- **建议修复**：上传时落库记录归属项目与上传人，读取改走受控接口（如 `GET /api/uploads/{id}`）并做 `AccessScope.requireVisible`；或按项目分目录 + 签名 URL。

### S-04 图片只校验扩展名，不校验真实内容

- **等级**：中
- **位置**：`UploadController`
- **现象**：白名单只看扩展名，伪造魔数的任意内容都能上传成功；响应 `Content-Type` 按扩展名推断。若后续放宽扩展名或浏览器发生 MIME 嗅探，存在存储型 XSS 风险。
- **对应用例**：UP-015
- **建议修复**：补魔数校验（PNG/JPEG/GIF/WebP/BMP 文件头），响应统一加 `X-Content-Type-Options: nosniff`，图片以 `Content-Disposition: inline` + 固定安全类型返回。

### S-05 富文本字段原样回显，转义责任全在前端

- **等级**：中
- **现象**：标题/描述中的 `<script>`、`<img onerror=...>` 等载荷入库后原样返回，后端不做任何过滤或转义。前端若用 `innerHTML` 渲染即形成存储型 XSS。
- **对应用例**：SEC-015
- **建议修复**：前端统一走文本节点渲染（`textContent`）；后端可选做入库白名单过滤，并补 `nosniff` 响应头。

### S-06 404 先于 403 判定 → 资源存在性披露

- **等级**：低
- **现象**：越权访问时先查存在再判权限，「不存在」返回 404、「存在但无权」返回 403，状态码差异可用于枚举真实 id。
- **对应用例**：PERM-020
- **建议修复**：对无权访问的资源统一返回 404。

## 四、设计一致性 / 前端交互风险（现状确认）

| 编号 | 现象 | 风险 | 建议 |
| --- | --- | --- | --- |
| USER-036 | 编辑用户省略 `projectIds` 会清空全部项目绑定（`resolveProjects(null)` 返回空集合，整体覆盖语义） | **高**：前端若只回传改动字段，会静默剥夺用户全部项目权限 | 明确区分「省略=不变」与「传空数组=清空」，或前端强制全量回传 |
| USER-030 | 编辑用户省略 `enabled` 等于启用（`req.enabled()==null \|\| req.enabled()`） | 中：禁用态账号被部分更新意外启用 | `enabled` 用 `Boolean` 三态判定，null 表示不变 |
| USER-010 | 创建用户时 `enabled=false` 被忽略（`create` 无条件 `setEnabled(true)`） | 低：无法「新建即停用」 | 创建时尊重入参，或前端去掉该选项 |
| ROLE-025 | `users.role` 是自由字符串，与 `roles` 表无外键/校验 | 中：删角色时按 `countByRoleCode` 统计，拼写不一致的引用统计不到，产生悬空引用 | 创建/编辑用户时校验 role 存在于角色表 |
| ROLE-018 | 内置角色允许改名（`update` 无 builtin 守卫，`delete` 有） | 中：前端按名称展示的角色语义可被改写 | `update` 对 builtin 角色只允许改描述，或整体拒绝 |
| ROLE-010 | 创建角色响应 `userCount` 恒为 0（写死 `0L`），列表接口才真实统计 | 低：前端用创建返回值渲染计数会显示 0 | 创建后按 code 统计再返回 |
| TC-009 | 创建测试用例不校验项目是否存在 | 中：与缺陷/需求模块策略不一致，可产生悬空 projectId | 三个业务模块统一校验项目存在性 |

## 六、其他已验证的接口行为（非缺陷，供前端联调参考）

- `POST /api/uploads` 成功返回 **200**（不是 201），响应体只有 `{"url": "/uploads/<uuid>.<ext>"}`。
- **文档模块没有 `GET /api/docs/{id}` 详情端点**，请求返回 405；读单条请用列表过滤，读内容用版本下载接口。
- 写操作 `projectId` 为空返回 **400**「请选择所属项目」；读操作 `projectId` 为空返回 **403**「无权访问该资源」——两侧口径不同，前端提示需区分。
- `POST /api/auth/logout` **不幂等**：token 吊销后再次登出返回 401（登出接口本身在 AuthFilter 之后）。
- 改密成功后**不续签 token**，该用户全部 token（含当前会话）立即失效，前端必须跳登录页。
- 登录限流：窗口 10 分钟、阈值 5 次失败、锁定 10 分钟；**第 5 次失败仍返回 400，第 6 次才返回 429**；登录成功即清零。内存级实现，服务重启后计数清零。
- 缺陷序号 `seq` 在项目内自增，跨项目改派会重新分配序号。
- 看板 `passRate` 用 Java `Math.round(pass*1000.0/executed)/10.0`（四舍五入到 0.1），`executed = total - NOT_RUN`，`executed=0` 时 `passRate=0`。
- 非法枚举查询参数走 `IllegalArgumentException` 分支，返回业务体 `{"error": ...}` 而非框架默认错误体。
